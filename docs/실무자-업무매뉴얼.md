# 매출·수수료 관리 실무자 업무 매뉴얼

이 문서는 매출·세무·전산 업무를 처음 맡은 분도 따라 할 수 있게 작성했습니다. 어려운 용어는 바로 풀어 설명합니다.

## 1. 이 프로그램으로 하는 일

매장 POS, 라이브방송, 온라인 판매 자료를 모아 입점업체별 매출을 기록합니다. 카드사·PG(온라인 결제를 처리하는 회사) 정산 자료와 은행에 실제 들어온 돈도 비교합니다. 계약에 따라 건물주가 받을 수수료를 월별로 계산하고, 그 금액을 업체가 납부했는지 표시합니다.

매출 자료는 수동 입력 또는 CSV 파일 업로드로 등록합니다. POS·쇼핑몰·은행에 자동으로 접속하는 프로그램은 아직 연결되어 있지 않습니다. 따라서 원본 자료를 정해진 주기로 내려받아 입력해야 합니다.

## 2. 먼저 알아둘 말

| 화면의 말 | 쉽게 말하면 |
|---|---|
| 입점업체 | 건물 안에서 판매하는 업체 |
| 채널 | 매출이 발생한 곳. 예: 공용 POS, 라이브방송, 온라인몰 |
| 매출 이벤트 | 매출, 취소, 환불처럼 주문에 생긴 한 번의 일 |
| 정산 참조번호 | 카드사·PG가 정산 건을 구분하기 위해 붙인 번호 |
| 수수료 기준액 | 계약에 따라 수수료율을 적용하는 매출 금액 |
| 수수료 부가세 | 건물주가 청구하는 수수료에 별도로 붙는 부가세 |
| CSV 파일 | 엑셀에서 열 수 있는 표 형식 파일 |
| 명세 스냅샷 | 특정 월의 거래와 수수료를 계산해 저장한 확정본 |

## 3. 누가 무엇을 할 수 있나요?

| 사용자 | 할 수 있는 일 |
|---|---|
| 관리자 | 전체 자료 조회, 업체·채널 등록, 거래와 정산 관리, 감사 이력 확인 |
| 정산담당자 | 업체·채널 등록, 거래와 입금 자료 등록, 수수료 명세 생성·수납 처리 |
| 입점업체 | 본인 업체의 매출과 수수료 명세 조회, 본인 자료 내려받기 |

아이디는 프로그램에 가입해서 직접 만드는 방식이 아닙니다. 관리자에게 요청해 발급받으세요. 입점업체 계정으로 로그인하면 다른 업체의 거래는 볼 수 없습니다.

## 4. 처음 한 번 하는 준비

1. 관리자가 **입점업체** 화면에서 업체를 등록합니다. 업체명은 매출 CSV의 `tenant` 칸과 똑같이 적어야 합니다.
2. 계약서에서 수수료율과 과세 구분을 확인해 입력합니다. 기본 수수료율은 10%이지만 계약서 내용이 우선입니다.
3. **판매 채널** 화면에서 공용 POS, 온라인몰, 라이브방송 등 매출이 발생하는 곳을 등록합니다.
4. 입점업체 담당자와 정산담당자 계정을 관리자에게 요청합니다.
5. 각 채널에서 매출 파일과 정산 파일을 내려받을 담당자, 내려받는 날짜, 파일 보관 위치를 정합니다.
6. 관리자·정산담당자는 **연동 준비** 화면에서 POS·온라인/라이브·PG·은행별로 업체에 확인할 항목을 봅니다. 업체별 계약과 기술담당자가 정해지면 공식 자료·샌드박스·권한을 받아 연동을 별도로 시험합니다.

업체 등록 후 수수료율이나 과세 구분이 바뀌면 다음 자료를 넣기 전에 관리자에게 알리세요. 과거 기간의 명세는 생성 당시 숫자를 보관합니다.

## 5. 매일 또는 영업일마다 매출 등록하기

### 방법 A: 화면에서 한 건씩 등록

1. **매출 원장**을 엽니다.
2. 업체, 채널, 주문번호, 유형, 발생일, 실제 결제액을 입력합니다.
3. 실제 결제액은 고객이 할인 적용 후 실제 낸 금액입니다. 할인 전 가격이 아닙니다.
4. 상품 부가세가 화면에서 자동 계산되더라도 POS 영수증이나 세금 자료와 다른 경우에는 확인된 세액을 입력합니다. 혼합과세 업체는 거래별 세액을 꼭 입력해야 합니다.
5. **원장에 추가**를 누릅니다. 저장한 뒤 매출 목록에서 업체·주문번호·금액을 확인합니다.

### 방법 B: 매출 CSV 파일 올리기

1. POS나 판매 채널에서 해당 기간의 주문 자료를 내려받습니다.
2. 프로그램에 등록된 업체명과 채널명을 확인합니다.
3. CSV 필수 열과 금액을 점검합니다. 자세한 예시는 아래 **CSV 파일 작성법**을 보세요.
4. **매출 원장** 화면의 CSV 가져오기에서 채널을 고르고 파일을 올립니다.
5. 성공 메시지가 나오면 매출 목록이나 CSV 내려받기로 몇 건을 대조합니다. 오류가 나오면 화면에 적힌 행 번호를 고쳐 다시 올립니다.

파일 전체의 형식과 값이 먼저 검사됩니다. 잘못된 행이 있으면 그 파일에서는 매출을 저장하지 않습니다. 이미 등록된 주문 이벤트는 중복으로 들어가지 않습니다. 같은 파일 자체를 다시 올리는 것도 차단됩니다.

### 환불·취소는 원래 매출을 지우지 않습니다

환불이나 취소가 생기면 **매출 원장**에 새 거래로 추가합니다. 유형은 환불 또는 취소를 선택하고, 실제 환불액은 양수로 입력합니다. 프로그램이 원장에는 음수로 기록해 원래 매출과 취소 이력을 모두 남깁니다. 환불을 이유로 원래 매출 행을 수정하거나 삭제하지 마세요.

### 품목·일자·월별 매출 확인하고 출력하기

1. 메뉴에서 **매출 보고서**를 엽니다. 관리자와 정산담당자는 업체를 고를 수 있고, 입점업체 계정은 본인 업체 자료만 나옵니다.
2. 시작일과 종료일을 정하고 필요하면 채널도 선택한 뒤 **조회**를 누릅니다. 시작일은 종료일보다 늦을 수 없습니다.
3. 위쪽 숫자에서 실제 결제액, 환불액, 취소액, 순매출, 순수량을 확인합니다. 아래에는 **품목별 판매현황**, **일자별 매출총계**, **월간 매출합계**가 표시됩니다.
4. **인쇄 · PDF 저장**을 누릅니다. 인쇄 창에서 프린터를 고르거나 **PDF로 저장**을 선택합니다. 인쇄본에는 조회 기간과 업체·채널 조건도 표시됩니다.
5. 엑셀에서 정리할 자료는 **품목별 CSV**, **일자별 CSV**, **월간 CSV** 중 필요한 파일을 내려받습니다. 조회한 기간과 필터가 내려받은 파일에도 적용됩니다.

**숫자 읽는 법:** 결제액은 할인 후 고객이 실제 낸 금액입니다. 환불액과 취소액은 별도 열로 나오며 순매출에서 차감됩니다. 수량은 매출은 더하고 환불·취소는 빼서 순수량으로 보여 줍니다. 공급가액 순액은 업체의 과세 구분과 입력한 상품 부가세를 사용한 참고 값입니다. 최종 수수료 마감은 **수수료 정산** 화면의 계약 기준 명세로 확인하세요.

품목 수량은 POS 자료에 품목별 수량이 있어야 정확합니다. 직접 등록할 때는 실제 개수를 입력하고, CSV 가져오기에서는 선택 열 `quantity`를 사용합니다. 매출·환불·취소 모두 파일에는 양의 수량을 넣으면 프로그램이 환불·취소를 음수로 기록합니다. 수량이 비어 있거나 열이 없으면 1개로 처리합니다. 과거 자료도 수량 정보가 없으므로 각각 1개로 표시됩니다. 품목별 수량이 중요한 매장은 POS 업체와 협의해 품목명과 수량을 함께 내보내세요.

## 6. 카드·PG 정산과 통장 입금 맞춰 보기

카드사나 PG는 여러 주문의 돈을 모아 한 번에 입금하는 경우가 많습니다. 주문 한 건씩 통장 거래와 맞추기보다, 카드사·PG 자료에 있는 **정산 참조번호**별로 비교합니다.

1. 카드사·PG 정산 자료에서 정산 참조번호, 정산일, 입금 예정액, 결제 수수료를 확인합니다.
2. 통장 거래내역에서 실제 입금액과 은행 거래번호를 확인합니다.
3. **입금 대사** 화면에서 정산 묶음을 한 건씩 등록하거나 CSV로 올립니다.
4. 예정액과 실제 입금액이 같은지 확인합니다. 다르면 **확인필요** 상태를 보고 정산 자료, 수수료, 입금일, 참조번호를 다시 대조합니다.
5. 차이가 해결되기 전에는 자료를 지우거나 금액을 임의로 맞추지 말고, 원본 자료와 확인 내용을 관리자에게 전달합니다.

이 화면은 차이를 보여 주는 기록장입니다. 은행에 접속하거나 돈을 이체하지 않습니다. 업체의 판매대금은 계약된 카드사·PG의 지급 절차를 따릅니다.

## 7. 매월 수수료 마감하기

마감 전에 해당 월의 POS·온라인·라이브 매출, 취소·환불, 정산 자료가 모두 들어왔는지 확인합니다. 누락된 채널이 있으면 명세를 만들기 전에 추가 등록하세요.

1. **수수료 정산** 화면에서 마감할 월을 선택합니다.
2. 먼저 한 업체만 선택해 명세를 만들고 매출 기준액, 수수료, 수수료 부가세를 계약서와 대조할 수 있습니다. 이상이 없으면 전체 업체 명세를 생성합니다.
3. 업체별 명세를 확인합니다. 과세 업체는 상품 부가세를 뺀 금액을 기준으로 계산하고, 면세 업체는 등록된 면세 구분에 따라 계산합니다. 최종 적용은 계약과 세무 담당자 확인을 따릅니다.
4. 명세가 맞으면 업체와 공유하고 납부를 요청합니다.
5. 실제 수수료를 받은 뒤에만 **수납 처리**를 누릅니다. 이 표시는 업체 수수료 납부 확인입니다. 카드·PG 매출 정산금을 받았다는 표시와는 다릅니다.
6. 생성한 명세는 그 달의 확정본입니다. 나중에 거래가 추가되거나 환불이 발생해도 자동으로 다시 계산되지 않습니다. 정정은 관리자에게 알리고 계약에 맞는 다음 기간 조정 방법을 정합니다.

환불이 매출보다 커지는 등 계산을 진행할 수 없는 경우에는 임의로 다른 달 거래를 바꾸지 마세요. 관리자와 회계 담당자가 이월 처리 방법을 정해야 합니다.

## 8. 아르카온 관리·분석 화면 보기

**아르카온 분석**은 현재 프로그램에 들어온 자료를 모아 사람이 확인해야 할 내용을 보여줍니다. 관리자·정산담당자는 입금 차이, 정산 참조번호 연결, 세액이 결제액보다 큰 거래, 이번 달 자료가 없는 활성 채널을 볼 수 있습니다. 입점업체 계정에는 본인 업체의 숫자만 보입니다.

- **입금 차이 확인:** 정산 예정액과 통장 실제 입금액이 다른 건입니다. 원본 파일을 열어 참조번호, 지급일, 수수료를 확인하세요.
- **참조번호 확인:** PG 정산번호가 매출 행에도 기록되어 있는지 살펴보라는 뜻입니다. 주문 자료에 정산번호를 제공하지 않는 채널은 운영자가 참고만 합니다.
- **자료 수집 확인:** 해당 채널에 매출이 없다는 확정이 아닙니다. 판매가 없었는지, 파일을 아직 올리지 않았는지 먼저 확인합니다.
- **환불 이월 검토:** 환불이 해당 기간 매출을 초과해 수수료 기준액이 마이너스일 수 있습니다. 담당 관리자와 회계 담당자에게 확인합니다.

이 화면은 이상 징후와 이유를 보여주는 보조도구입니다. 자동으로 원장 금액을 고치거나 송금하지 않습니다. 원본 POS·판매·PG·은행 자료와 대조한 뒤 담당자가 처리합니다.

## 9. CSV 파일 작성법

CSV 파일은 UTF-8 형식을 권장합니다. 첫 줄의 열 이름은 아래처럼 정확히 적습니다. 금액은 원 단위 정수로 작성하고 `원`이나 통화 기호는 붙이지 않습니다.

### 매출·환불 파일

필수 열:

```csv
event_id,order_id,event_type,date,tenant,amount,tax_amount
POS-20261008-001,주문-001,sale,2026-10-08,아리랑상점,11000,1000
POS-20261008-002,주문-002,refund,2026-10-08,아리랑상점,5500,500
```

선택 열: `quantity,discount,product,payment_method,settlement_ref`

- `event_id`: POS나 판매 채널의 거래 고유번호입니다. 가능하면 원본 번호를 그대로 넣습니다.
- `order_id`: 주문번호입니다. 취소·환불도 알아볼 수 있게 원 주문번호를 넣습니다.
- `event_type`: `sale` 매출, `refund` 환불, `cancel` 취소 중 하나입니다.
- `date`: 거래가 발생한 날로 `YYYY-MM-DD` 형식입니다.
- `tenant`: 프로그램에 등록한 업체명과 글자까지 같아야 합니다.
- `amount`: 고객이 실제 낸 금액입니다. 환불·취소도 양수로 입력하면 프로그램이 음수로 저장합니다.
- `tax_amount`: 상품에 붙은 부가세입니다. 과세 업체는 비워 두면 결제액의 1/11을 계산합니다. 면세 업체는 0, 혼합과세 업체는 정확한 세액을 적습니다.
- `quantity`: 해당 거래의 품목 수량입니다. 매출·환불·취소 모두 양의 정수로 적습니다. 환불·취소는 프로그램 원장에 음수 수량으로 저장됩니다. 생략하면 1개입니다.
- `discount`: 할인액을 참고로 남길 때 입력합니다. `amount`는 이미 할인을 반영한 실제 결제액이어야 합니다.

### 정산 묶음 파일

필수 열:

```csv
settlement_ref,settlement_date,expected_amount,received_amount
CARD-20261008-A,2026-10-08,980000,980000
```

선택 열: `provider_fee,bank_ref`

- `settlement_ref`: 카드사·PG 자료에 적힌 정산 참조번호입니다.
- `settlement_date`: 정산 예정일 또는 정산일을 `YYYY-MM-DD`로 입력합니다.
- `expected_amount`: 해당 정산 건으로 입금되어야 할 금액입니다. 카드사·PG의 정산 내역을 기준으로 합니다.
- `received_amount`: 통장에 실제 찍힌 입금액입니다.
- `provider_fee`: 카드사·PG 결제 수수료입니다. 제공 자료에 없으면 비워 둘 수 있습니다.
- `bank_ref`: 통장 거래번호 등 나중에 찾아볼 수 있는 번호입니다.

같은 채널과 정산 참조번호는 한 번만 등록할 수 있습니다. 자료를 확정하기 전에 기간, 채널, 참조번호와 금액을 확인하세요.

## 10. 잘못 입력했거나 이상한 숫자가 보일 때

- **CSV에 업체를 찾을 수 없다는 오류:** 업체명이 프로그램 등록 이름과 같은지 확인합니다.
- **같은 파일이라고 나오는 경우:** 이미 올린 파일인지 확인합니다. 먼저 매출 원장 또는 입금 대사 화면에서 자료가 들어갔는지 찾아봅니다.
- **주문 이벤트가 중복으로 들어오지 않은 경우:** 같은 채널에 같은 `event_id`가 이미 등록되었는지 확인합니다. 같은 거래를 다른 ID로 다시 만들지 마세요.
- **매출이 음수로 보이는 경우:** 환불·취소는 음수가 정상입니다. 매출 유형이 환불/취소로 잘못 선택되지 않았는지 확인합니다.
- **금액 차이가 있는 경우:** 원본 POS/PG/은행 자료, 업체, 기간, 채널, 참조번호, 할인·환불을 순서대로 대조합니다.
- **이미 등록한 자료를 고쳐야 하는 경우:** 화면에서 원장을 직접 덮어쓰지 않습니다. 잘못된 행과 원본 증빙을 보관하고 관리자에게 알려 정정 기록을 남깁니다. 특히 수수료 명세 생성 후에는 임의로 거래를 다시 올리지 마세요.
